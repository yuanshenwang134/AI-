# 视觉确认（可量化部分）：待确认徽章的清晰度与区分度（2026-09-26）

> 承接你们的判断："剩下的是浏览器视觉确认，重点看橙色徽章的文字是否清晰、
> '待确认'与'未中'是否容易区分。无需再改判定逻辑。"
> 判定逻辑本轮**一行没动**；这里做的是把"清晰/容易区分"变成可量的数字，

## 一、结论（先说数字）

用 `web/styles.css` 里的真实取值算 WCAG 对比度（`.tl-badge` 是 11.5px 加粗 = 小字号，
AA 要求 ≥ 4.5:1）：

| 徽章 | 文字 / 底色 | 对比度 | 判定 |
| --- | --- | --- | --- |
| 命中 `made` | `#ffffff` / `#22a06b` | 3.33:1 | 未达 AA |
| 未中 `miss` | `#5b6472` / `#c9ced6` | 3.78:1 | 未达 AA |
| **待确认 `needs`** | `#ffffff` / `#f5a623` | **2.03:1** | **未达 AA，三者里最差** |
| 主队 `h` | `#ffffff` / `#2f6fed` | 4.55:1 | 通过 |
| 客队 `a` | `#ffffff` / `#f2762e` | 2.84:1 | 未达 AA |

**"清晰"这一项：待确认确实是三者里最差的**（白字压在橙色上，2.03:1），
不是"看着还行"的问题，是能算出来不够。

**"容易区分"这一项：待确认 vs 未中没问题，但待确认 vs 客队有问题** ——
底色色差（CIEDE2000）：

```
待确认 vs 未中   ΔE = 34.1   （好区分 ✓）
待确认 vs 客队   ΔE = 18.3   ← 两者都是橙色，而且在同一行紧挨着
待确认 vs 命中   ΔE = 43.9
```

也就是说：**"待确认"最容易被误读的地方不是"未中"，而是旁边的队别徽章**。

## 二、三个方案（都只动样式，不动判定逻辑）

| 方案 | 做法 | 对比度 | 附带效果 |
| --- | --- | --- | --- |
| **A（最小改动）** | 只给 `.needs` 加深色字 `color:#1f2937` | **7.24:1** ✓ | 仍与客队同为橙色实心（ΔE 18.3 不变） |
| **B（推荐）** | `.needs` 改描边样式：白底 + 橙框 + 深橙字（`#fff` / `1px #f5a623` / `#8a5a00`） | **5.93:1** ✓ | 同时**消除与客队橙的撞色**（不再是实心橙） |
| **C（顺手统一）** | 三态都用深色字：命中 `#06301f`、未中 `#3a424e`、待确认 `#1f2937` | 4.35 / 6.42 / 7.24 | 命中 4.35 仍差 4.5 一点点，要把绿色调深才行（属设计系统改动，建议单独立项） |

我的建议：**先做 A 或 B**（一行 CSS），C 里"命中"那条涉及改主题色，别顺手一起动。
