## 一、他们这轮的边界修正：验证通过

他们把徽章文案改成与配色共用同一个判据：

```
:class="resultClass(e)"  ...  {{ resultClass(e) === 'needs' ? '待确认' : e.made ? … : '未中' }}
```

我的验证方式不是"再抄一份逻辑"，而是**从 `overview.js` 里把这段模板表达式取出来求值**，
对 6 行输入矩阵逐个比对（见第三节的测试）。结论：`made` 为空且缺 `result` 的行，
徽章是橙色、文案是"待确认" —— 一致 ✓。

## 二、我复核时发现的同类不一致（已修）

同一个"未知"判据在别处还各写了一套，边界行会走岔：

| 位置 | 改前 | 改后 |
| --- | --- | --- |
| `web/pages/overview.js` 时间轴筛选 | "未中"口径用 `(e.made \|\| e.result === 'unknown')`、"待确认"口径用 `e.result !== 'unknown'` → **缺 result 的未知行会同时出现在"未中"里、从"待确认"里消失** | 三个分支统一走 `resultClass(e) === 'needs'` |
| `web/data.js` `D.shotsFromTimeline` | `filter(e.result !== "unknown")` | `filter(!D.isUnknown(e))` |
| `web/data.js` `D.shotsFromPlayers` | `if (s.result === "unknown") return;` | `if (D.isUnknown(s)) return;` |

新增的唯一判据（`web/data.js`）：

```js
D.isUnknown = function (e) {
  return !!e && (e.result === 'unknown' || e.made === null || e.made === undefined);
};
```

徽章配色、文案、时间轴筛选、投篮图兜底**四处全部走它**。
后端的口径没动：`rules.shot_chart` 依旧排除未知出手（按你们的决定，投篮图继续不画未知），
这次只是让**前端兜底**与它对齐 —— 否则一份缺 `result` 的旧产物会在兜底路径里冒出一个红点。
