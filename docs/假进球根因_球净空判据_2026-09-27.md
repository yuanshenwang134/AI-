# 假进球的真正根因：球不是质点（净空判据）　2026-09-27

> 本文修正 `docs/假进球_nathan3.4s_2026-09-26.md` 里我给出的根因。
> 结论一句话：**那一球判错的不是"筐心不知道在哪"，而是判据把球当成了质点。**

---

## 1. 先认错：上一轮的两处错

| 上一轮的说法 | 实际情况 |
| --- | --- |
| "球心横向偏移 = 0.00×rx（正筐心穿过）" | **算错了**。当时拿 `cross_x` 减的是**整段视频的筐位中值** (551.8,153.5)。镜头在动，t=3.40s 那一刻的筐心是 **533.4**。相对**当时**筐心，偏移是 **+19px = +0.63×rx**。 |
| "根因是筐心不确定度 32–40px ≈ rx=31px，分辨率不够" | **不成立**。`robust_drift_px=[31.1,37.6]` 量的是**整段漂移**，而这段素材 `camera_motion` 判定是 `slightly_moving`（8.15 px/s）—— 那 31px 是**真实的镜头摇摄**、被跟踪得好好的。t=3.40s 附近的**局部**残差只有 **2.5px（0.09×rx）**。 |
| "把整段漂移当不确定度会让所有判进变未知 —— 召回会掉，但精确率才对得起来" | 这个取舍我按字面实施了，结果是 **nathan 5 个真进球全变未知（召回 0）**，而假进球也没被"解释"清楚。属于用错工具。 |

## 2. 真正的根因：`rim_inner = 0.85` 把球当质点

判进的条件原来是「穿越点横向偏移 ≤ `rim_inner × rx` = 0.85×rx」。
这等价于假设**球是一个点** —— 只有点才能偏移 0.85×rx 还"穿过"篮圈。

球有半径。球心偏移 `d`、球半径 `r_b`、篮圈内半径 `r_r` 时，**干净穿过**要求

```
d ≤ r_r - r_b      →      d/rx ≤ 1 - r_b/r_r
```

实测这段素材（t=3.40s 那一帧直接跑检测器）：

| 目标 | 检测框 | 半径 |
| --- | --- | --- |
| basketball | (538,131)-(570,165)，32×33px | **≈16px**（含一点运动模糊，会略偏大） |
| rim | (501,149)-(564,167)，宽 62~70px | **≈31~35px** |

`16/29 ≈ 0.55`，而物理常数 `球直径 0.24m / 篮圈内径 0.45m = 0.533` —— 两者一致，
所以用**物理常数**（不受逐帧框宽噪声影响）：

```
净空门槛 = 1 - 0.24/0.45 = 0.467 × rx
```

对照实测的 4 次穿筐事件（用**逐帧**筐位算偏移，单位 rx）：

| 出手时刻 | 穿越时刻 | 球心偏移 | 人工真值 | 旧判据 0.85 | 新判据 0.467 |
| --- | --- | --- | --- | --- | --- |
| 2.64s | 3.40s | **+0.63** | **不中**（贴筐沿/网外掉下去） | ❌ 判进（假进球） | ✅ 不判进 |
| 4.91s | 7.35s | −0.20 | 进 | 进 | 进 |
| 15.55s | 17.79s | −0.12 | 进 | 进 | 进 |
| 23.66s | 25.22s | −0.42 | 进 | 进 | 进 |

**0.467 把"人工确认的那次不中"和"3 次人工确认的进球"正好分开**，
而且这是从物理尺寸推出来的，不是拿这段素材调出来的。

## 3. 修法（已实施）

`src/aihoop/hoop.py`：

1. `HoopConfig` 新增 `ball_diameter_m=0.24`、`rim_diameter_m=0.45`；
   `clearance = 1 - ball/rim = 0.467`。
2. **三处**横向门槛都改成"取更严者" `min(档位系数, clearance)`：
   * 判进（`detect_shots` 主判据）
   * 筐口空洞插值的可信性闸门（`hole_rim_tighten` 那一处）
   * 趋势外推档的落点闸门（`extrap_rim_inner` 那一处，默认 0.6 → 实际生效 0.467）
3. 新增结果档 **`cross_rim_contact`（贴筐掠过，结果未知）**：
   `0.467×rx < |偏移| ≤ rx` 时，球**一定压到了篮圈**，但"进没进"单目看不出来
   （碰筐后弹进去也是进），所以 `made = None` + `needs_review`，**既不算进也不算不中**。
   超出 `1.15×rx` 仍然判 `miss`。
4. **筐位不确定度改用局部残差**：新增 `HoopTrack.local_uncertainty(t, window_s=1.5)`
   = 原始样本相对中值滤波轨迹的残差在 t 附近的 10~90% 区间；
   `hoop_uncertainty_px=None` 时自动取它（手标筐 = 0）。
   仍保留 `hoop_uncertainty_max_frac=0.5`：局部不确定度 ≥ 半个篮圈半径时
   **既不判进也不判不中**，只报 `cross_hoop_uncertain`。
   为什么必须换：整段漂移量里混着镜头运动，用它会把 nathan 的 3 个真进球一起否掉。

## 5. 同时要收回的一条旧结论（含我自己的一个错误推断）

`docs/开源调研_提高投篮识别率_2026-09-24.md` 与 `docs/投篮判定_米制门槛与外推开关_2026-09-25.md`

（0.58×rx）会归到 `cross_rim_contact`（未知）"。数字 0.58×rx / 18px 是从旧文档里
抄来的，我**假设**它指的就是这一次事件 —— 假设错了。

队友侧的离线对照先发现"打开外推后仍是 3 个实测命中 + 1 条推算建议"，与我说法不一致；
我随后用**同一次运行**的数据（球轨迹 + 筐轨迹都取自这一次 `VideoSource.run`，
不再拼凑两次转储）复算，结果如下（`scripts/ab_extrapolation_selfconsistent.py`，与产品实测逐条一致）：

| 出手 | 穿越 | 默认（外推关） | 打开外推 |
| --- | --- | --- | --- |
| 2.64s | 3.404s | `cross_rim_contact` 偏移 +0.63×rx | **同左（没有被"洗白"）** |
| 4.91s | 7.345s | `cross_measured` −0.21×rx | 同左 |
| 15.55s | 17.793s | `cross_measured` −0.12×rx | 同左 |
| 19.36s | 21.141s | 无穿筐证据（未知） | **`cross_extrapolated` 偏移 −0.01×rx** |
| 23.66s | 25.218s | `cross_measured` −0.42×rx | 同左 |

结论（以这份为准）：
* 那个外推交点横向偏移 **−0.3px = −0.01×rx**（几乎正筐心），**不是 0.58×rx**，
  所以在净空门槛之内、被正常接受；按产品分级它只是 `suggested_made`（建议），
  不计入已确认命中。
* 开关的实际收益是：把"19.36s 这条没有穿筐证据的未知"升级成"带**建议**的未知"
  （复核者多一条线索），而不是提高已确认命中数（两种设置下**都是 3 个**）。
* 开关**不会**把 2.64s 那次假进球重新变成进球（仍是 `cross_rim_contact`）——
  这一点很重要，说明净空判据与开关叠加是安全的。
* 数据来源教训：以后做这种 A/B，**必须用同一次运行的球轨迹与筐轨迹**。
  队友侧提出"配对数据来源尚未确认"是对的；我原先的 probe 把两次不同运行的东西配在一起，
  这次侥幸结论相同，但方法上不成立。

## 6. 措辞更正：图像平面的判据，不能说成"一定碰到筐"

我把 `cross_rim_contact` 描述成"球**一定**压到了篮圈"，队友侧在复核页文案里
改成了**"球的轨迹靠近筐沿，可能擦筐；是否进球需要人工确认"**，并说明理由：
横向净空是保守的**图像空间**近似，二维投影不能唯一确定三维接触。

**这条我接受，已在代码注释里同步改写。** 准确的表述是：

* 能确定的：这种横向偏移**不足以支撑"干净穿筐"的结论**（所以不许判进）；
* 不能确定的：球在三维空间里到底碰没碰到筐（球可能从筐前面/后面掠过）。

这也和我自己在《开源调研》里写的 P0 结论一致：瓶颈是逐帧几何精度，
没有相机矩阵/深度，单目只能在图像平面上做保守判断。

## 7. 诚实的遗留问题

1. **nathan 的 9.14s / 19.36s 两次出手仍无实测穿筐证据**（未知）。19.36s 那条在打开外推后
   会得到一条**建议**（外推穿越点 21.141s，偏移 −0.01×rx）；9.14s 连外推都没有。
   还是要人工看 `out/nathan_review_clips/candidate_004/006.mp4` 这两段。
2. **23.66s 那个真进球卡在阈值边上**：偏移 0.42×rx，门槛 0.467×rx，只差 0.047×rx ≈ 1.4px。
   球心检测再偏 1.4px 它就会从"进球"变成"贴筐掠过（未知）"。这是净空判据的固有代价。
3. **"贴筐掠过也可能是进球"（筐上弹一下滚进去）**：新档位把它标成"未知"而不是"不中"，
   这是对的，但也意味着**产品在这类球上永远需要人工确认**。想减少人工量需要深度/球场几何（P0-b）。
4. **措辞边界**：`cross_rim_contact` 只表示"图像平面上球体与篮圈重叠、不足以支撑干净穿筐"，
   **不能**对外说成"球一定碰到了筐"（单目无法确定三维接触）。队友侧已按此改文案，我同意。
5. ~~外推开关的收益需重测~~ → 已测，见第 5 节：收益是"多一条建议"，已确认命中数不变（3 个），
   且不会让 2.64s 的假进球复活。
6. `local_uncertainty` 在窗口内样本不足 3 个时会**退回整段残差**，不是任何情况下都严格局部；
   采样率低或镜头切换附近要留意（队友侧指出，本轮保留该回退）。
