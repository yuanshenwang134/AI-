# 「不标定球场就不给分析」：真 bug，已修（2026-09-27）

> 用户反馈（原话）：**"我给了文件路径以后，篮筐标点球场标定进球标注都是灰的……而且不标定球场他就是不给分析呀"**
> 这里把三件事一次说清楚：① 灰按钮的真实原因 ② 随机种子是什么 ③ 为什么会被拒、修了什么、怎么验证的。

---

## 一、三个控件变灰：不是权限，是"页面以为后端没连上"

**绑定关系（读的是源码）**：

| 控件 | 位置 | 禁用条件 |
| --- | --- | --- |
| 「在画面上标篮筐」 | `web/pages/upload.js:1097` | `:disabled="!S.backendOk"` |
| 「标球场（点场地特征点）」 | `upload.js:1098`、`1111` | `:disabled="!S.backendOk"` |
| 「选择本地视频上传」 | `upload.js:1087` | `:disabled="!S.backendOk \|\| (health && health.stale)"` |

页面在 `!S.backendOk` 时还会显示两处提示：红字"后端没连上：先双击项目根目录的「启动后端.bat」"（`upload.js:1050`）、右上角状态标签 `{{ api.base }}` + "未连接（演示数据模式）"（`upload.js:1160-1161`）。

**为什么"明明后端在跑"还是灰**：`S.backendOk` 是**页面加载时探测一次**决定的（`app.js:149 bootstrap()`），之后**不会自动重试**。所以：

* 打开页面的那一刻后端正好不在（还没双击 .bat，或者它正在自动重启 —— `启动后端.bat` 会监听 `src/aihoop/*.py` 自动重启，改代码后有两三秒的空窗），
* 页面就会一直停在"未连接"状态，直到用户手动恢复。

**恢复方式（两种都行）**：点**右上角「重新探测」**（`index.html:84`，调用 `probe()`），或直接**刷新页面**。

**本轮顺手加的**：`index.html` 里 14 个 `<script src="...?v=31">` 的缓存击穿版本号改成了 **`?v=32`** —— 否则普通 F5 可能仍用浏览器缓存的旧 `upload.js`（这文件自己的注释里就记着这个坑）。**保险起见用 Ctrl+F5 强制刷新一次。**

## 二、随机种子（seed）：只对"合成演示比赛"生效，真实视频不用它

* 后端只有一处用到它：`api.py:248 → synthetic_game(seed=req.seed, ...)`，
  内部 `sources.py:410-422 rng = random.Random(seed)`。
* **真实视频那条管线里没有任何随机数**（全仓 `random.` 只出现在合成数据与标定自检里），
  同一段素材每次跑结果都一样。所以这个输入框对视频分析是**空操作**。
* 界面原来的提示"相同 seed + 相同数据源 = 完全可复现的结果（答辩可复查）"对视频源是**误导**，
  已改成："只对「合成演示比赛」生效……**真实视频分析不用它**"，并在
  `tests/test_upload_payload.js` 里加了断言防止改回去。

## 三、不标定就不给分析：界面承诺和后端要求不一致（真 bug）

**事实链**：

1. 上传页引导第 2 步写着"标定球场（可选，推荐做）……**不标也能出比分、命中率、球员统计和战报**"（`upload.js:171-176`）。
2. 但「开始分析」的请求体（`upload.js:938-961`）**从来没有** `allow_no_calibration` 字段。
3. 后端 `JobCreate.allow_no_calibration: bool = False`（`api.py:174`），`_run_job` 里没标定就抛错（`api.py:280`）。

**复现（实测）**：POST `/api/jobs`（`source=video`、nathan、不带该字段）→ 返回 `job_id`（提交是成功的），
随后任务状态变 **`error`**：

```
status  error
error   RuntimeError: 尚未标定球场。请先标球场；只读比分可关闭球员检测并选 scoreboard 口径，
        只想验证投篮判定（不要球场坐标）可传 allow_no_calibration=true。
```

注意这是**任务失败**而不是提交失败 —— 界面显示"分析失败"，用户会觉得"软件坏了"，
而实际原因是一条面向开发者的提示。这就是"不标定就是不给分析"的真相。

**修复**（`upload.js`，`start()` 里）：

```js
if (this.form.source === 'video') {
  var hasCal = !!(this.calInfo && this.calInfo.exists);
  payload.allow_no_calibration = !hasCal;
  if (!hasCal) this.log('未标定球场：本次按「只判进球」跑（没有热图/战术图/2-3 分区分）；标定后这些位置类结论才会打开。');
}
```

同时把引导里那句改准确：不标定能给的是"出手/进/不中/未知、比分（分值按图像估计并标注）、命中率、
球员统计、文字战报"；**热图、战术图、2 分/3 分区分**才需要标定。

**验证（真跑，不是推断）**：同一个视频、同一个请求体，**只加这一个字段**：

```
任务已创建 job_id= 873833c62992
[  0s] running   6% 检测球员与篮球
[ 45s] running  50% 识别篮筐并判断进球
[ 50s] done    100% 分析完成
```

**门禁**：新增 `tests/test_upload_payload.js`（5 条断言：未标定必须带 `true`／已标定不能带／
未标定要有说明日志／jsonl 源不受影响／界面文案与行为一致），并在 `scripts/check_all.py`
里接成第 `8e/9` 步。完整门禁**全部通过**。

## 四、顺带发现的一个口径不一致（未修，记在待办）

球+筐那条路（`sources.py:2141`）把 `counts_for_score=counts_for_score and not team_unknown`，
所以**关闭球员检测**时出手会因"认不出谁投的"而不计入比分：nathan 实测 `score = {home: 0, away: 0}`，
而同一条判语写着"本片段 3 次命中，合计 6 分"。对比 hoopsight 那条路不受影响
（dairy `4:0`、fixedcam `6:0`）。

两个数字并排出现在界面上会显得自相矛盾 —— **演示时请打开球员检测**；
要不要把两条路的计分口径统一，属于产品口径决定，见待办 F7。
