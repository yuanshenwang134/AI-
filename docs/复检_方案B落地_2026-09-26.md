## 三、把可读性钉进回归测试

`tests/test_unknown_style.js` 新增一段：**从 `styles.css` 里正则取出 `.needs` 的
`background` / `color` 现算对比度**，并断言：

1. `.needs` 必须**显式**声明 `background` 与 `color`（不能靠继承基类的白字 —— 那正是 2.03:1 的来源）；
2. 对比度 **≥ 4.5:1**；
3. 底色与 `--away` 的 RGB 距离 **≥ 60**（防止再变回与客队同色系的实心橙）。

测试输出会打印实测值，便于日后复核：

```
待确认徽章：文字 #8a5a00 / 底色 #fff → 对比度 5.93:1；与客队底色 RGB 距离 250
Unknown-result rendering checks passed
```

这样"视觉确认"这一步就不再只靠人眼一次 —— 数值部分以后改坏了会被门禁挡下。

**但要说清楚边界**（队友侧也提了这一点，我同意）：
对比度是标准可判定量，可以当门禁用；而"与客队底色的 RGB 距离 ≥ 60"
只是**防退化的代理指标** —— 它能挡住"又变回和客队一样的实心橙"，
**不能替代人眼对区分度的判断**。区分度（尤其是"同一行相邻、颜色相近"这种场景）
最终仍以人工目视为准，测试只负责防止把已经确认过的方案悄悄改坏。
