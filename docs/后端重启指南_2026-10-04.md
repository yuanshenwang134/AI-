# 后端重启不了：原因与三种解法（2026-10-04）

## 1. 你遇到的现象

> "后端怎么重启？就算我把那个任务栏关了还是重启不了。"

任务管理器/任务栏里关掉的那个窗口**不是后端进程本身**。

## 2. 实测到的真相

在你机器上量到的：

```
netstat -ano | findstr :8000
  TCP    127.0.0.1:8000    0.0.0.0:0    LISTENING    4596

Get-Process 4596 -> python    启动于 2026/10/3 16:34:55
http://127.0.0.1:8000/api/health -> ok=True  stale=True  code_loaded_at=10-03 16:34:55
```

**PID 4596 是 16:34:55 启动的旧后端，一直没死，还占着 8000 端口。**

### 为什么会这样

`启动后端.bat` 用 `scripts/serve_reload.py` 启动，而 uvicorn 是它的**子进程**
（`subprocess.Popen`）。关掉控制台窗口时，父进程结束，但**子进程常常不跟着死**
—— 变成孤儿进程继续占着端口。

于是你再双击 `启动后端.bat`：新进程发现 8000 被占 → 立刻退出 →
**窗口一闪而过**，看起来就是"重启不了"。

（`--reload` 的坑项目里早就记过：Windows 下 multiprocessing 要建命名管道，
受限环境直接 WinError 5，所以当初才自己写了这个轮询式启动器。
副作用就是这次的孤儿进程问题。）

## 3. 三种解法（从省事到兜底）

### 解法 A：双击「重启后端.bat」（推荐）

新增的 `重启后端.bat` 会：

1. 用 `netstat -ano` 找出占着 8000 的是哪个 PID，并打印出它的启动时间；
2. `taskkill` 掉它，并**确认端口真的空了**（没空就再等一次）；
3. 在新窗口启动后端；
4. 轮询 `/api/health` 直到就绪，然后打印 `code_rev / code_loaded_at / stale`
   —— 你能直接看出"跑的是不是最新代码"。

如果第 2 步报权限不够（`Access denied`），用**管理员身份**再运行一次这个文件。

### 解法 B：任务管理器手动结束

1. `Ctrl+Shift+Esc` 打开任务管理器 → **详细信息**页；
2. 右键列标题 → 勾选 **PID**；
3. 找到 PID = `netstat` 里那个（这次是 **4596**），或者按启动时间排序找
   `16:34` 那个 `python.exe`；
4. 结束任务；
5. 再双击 `启动后端.bat`。

### 解法 C：直接杀掉所有 python（粗暴但有效）

任务管理器里把所有 `python.exe` 结束掉，然后重启。
（注意：如果你还有别的 python 程序在跑，会被一起停掉。）

## 4. 顺手把坑补上了

既然根因是"子进程变孤儿"，就从启动器这一侧修：

* `scripts/serve_reload.py` 新增：
  * `pids_listening(port)` —— 用 `netstat -ano` 查谁在监听；
  * `free_port(port)` —— 启动前清掉旧进程（`--kill-port` 开关，或 `重启后端.bat`）；
  * `cleanup_orphans(port)` —— **退出时（含 Ctrl+C、窗口被关）也尽力清掉**
    还占着端口的子进程，尽量不留孤儿；
  * 默认（不带 `--kill-port`）只**提醒**端口被占，不擅自杀进程。
* `启动后端.bat` 现在带上 `--kill-port`，所以"双击启动"本身就会先清端口。

### 实测（不动那个杀不掉的进程，换个端口验）

在 **8021** 上跑 `scripts/serve_reload.py 8021 --kill-port --no-reload`：

```
ok=True   stale=False
code_rev       = 10-04 15:55:54
code_loaded_at = 10-04 16:03:33
/api/frames_stable?video_path=... -> OK
```

说明启动器与新代码都正常。（8000 上那个孤儿进程由沙箱权限挡住，我这边杀不掉，
所以留给你用解法 A/B 处理。）

## 5. 怎么确认"后端跑的是不是最新代码"

任何时候打开：<http://127.0.0.1:8000/api/health>

```
"code_rev":      源码最后一次改动的时间
"code_loaded_at": 后端进程载入代码的时间
"stale":          true = 后端还是旧代码（code_rev 比 code_loaded_at 新）
```

**上传页也用这个**：`stale=true` 时上传按钮会被禁用并给出提示 ——
以前它只默默禁用、什么都不说，看起来就像软件坏了。
