## 2. 每条修法的理由（都是实测出来的，不是猜的）

### R1 基线位移：从"静默"改成"写进产物"
实测 game_04：画面开头约 8 秒**一条读数都没有**（Windows OCR 读不出主队 FHS 的数字，
我换过 5 种裁剪 × 3 种放大倍数逐一试过，`FHS` 后面的数字始终读不到），
于是基线被推迟到 `t=8.01s`（此时主队已是 33），主队那次 `31→33` 的得分被并进基线：
**终场 38:38 完全正确，事件表却少一条**。这不是算错，是**没声明**——对复盘产品来说，
静默漏计比报错更危险。所以：
- 产物里给出 `baseline_at = {home: 8.01, away: 8.01}`；
- 报告/接口直接写"主队、客队的基线取自 t=8.0s 的画面读数，该时刻之前的得分不在事件表里；
  要补全请填写起始比分后重跑"；
- 顺带发现两处装载点都没带这些字段（`_scoreboard_only()` 尤其明显：覆盖率恒为 1/1）。

### R2 收紧框：**必须用取值验证**，否则宁可不收
第一版我按"OCR 词坐标并集"收紧，框从 `[384,64,1152,172]` 收到 `[680,118,616,50]`（看着更贴真值），
**结果把主队数字切掉一位**：`33` 被读成 `3`，OCR 照样解析出 `"FHS 3 AHS 36"`，守卫只检查"能不能解析"
所以放行了，终场变成 `home=3`。因此加了取值一致性守卫：
> 收紧后读到的分数对**必须全部出现在宽框读到的分数对里**，且有效读数不少于宽框 − 1，才采纳。

在这段素材上，收紧**没有通过**该守卫 → 自动退回宽框 → 结果恢复正确（379/480、7 事件、38:38）。
即：**收紧是"可能更好"的优化，验证不过就不做**，而不是"改了就一定更准"。

### R3 文案与覆盖率：按口径说话
原写法在 `score_policy=scoreboard` 时把 8 条**比分牌事件**说成"视觉命中已计入总分"
（该任务 `meta.visual=null`，根本没有视觉层），并且 `frames_read` 恒为 1，
报告写成"读数覆盖 1/1"却给出 38:38 —— 反而降低可信度。现在分别写清覆盖率、
带入分与事件条数，只有真的走视觉路径时才提"视觉命中"。

## 4. 仍未解决（如实列出，别当成已修）

1. **读数覆盖率 79%（379/480）**：成因已查清，**不是框几何问题**（收紧无法改善，已实测）。
   分两类：① 开头约 8 秒主队数字 OCR 读不出（换裁剪/倍数都无效）；② 约 85 帧被 OCR
   读成单字符噪声（`0`、`3`），被 `max_delta` 正确拦掉（`rejected` 明细可见）。
   下一步可试：对比 `en-US` 之外的 OCR 语言、或在噪声帧上用"局部再放大 + 只取数字区"二次识别。
   **在修好之前，产品应始终显示覆盖率**（现在已经显示）。
2. **`probe_footage` / `check_video_fit` 的机器环境依赖**：缺 `YOLO_CONFIG_DIR`、`AIHOOP_MODELS`
   时会退化成"素材不行"的结论。建议在脚本里对缺失的关键环境变量**显式报错**，
   而不是给出看起来像结论的降级结果（这条是我复检时踩到并写进复检报告的）。
3. 本素材是**摇镜转播**，单张单应不适用，位置类结论仍应保持关闭（现在也是关闭的）。
