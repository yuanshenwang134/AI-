# 复核记录定位与未知结果契约修正

保留外部复核对 web/_test.js 的两处修正，以及建议行为检查的门禁接线。本轮不执行视频推理。

## 修改

1. timeline 与 needs_review 使用相同的时间排序并显式输出零基 index。旧记录按时间与球员匹配，容许两位小数时间舍入；优先分值一致的唯一候选，否则仅在时间/球员候选唯一时回退。多个候选时拒绝自动定位。当前代码原已含错误提示，本轮改成“这条记录无法定位到比赛事件，请刷新后重试”，并拒绝非整数下标。
2. `_shot_event` 和 `Shot.to_dict()` 在 result=unknown 时输出 made=null，覆盖时间线、复核列表和 Shot JSON。内部 Shot 的布尔占位仍保留，内部消费者仍须按 result 区分未知。检查了 CSV、统计、热区和总览筛选：原有 result 过滤继续有效；未知 CSV 值保持空白。此改动不能强制任意第三方消费者停止把 null 当 false，result 仍是三态结果的明确依据。
3. POST correct 的非空 value 仅允许 1/2/3，非法整数返回 HTTP 400；检查在读取比赛文件与写入 corrections 前执行。字段类型错误仍由请求模型处理。

## 验证

- 新增后端 3 项检查：未知 JSON/CSV；真实统计管线生成一致序号；HTTP 非法分值无文件读写。
- 新增前端 7 项定位检查：舍入、分值差异、重复候选、显式序号、越界回退、球员不符、定位失败提示。
- 后端测试仅使用临时产物，HTTP 测试不启动真实任务恢复。
- Python 新检查命名 test_shot_review_contract.py，纳入既有投篮测试发现规则；JS 新检查纳入前端门禁组。

旧的 game.json 不会因源代码修改自动更新，新字段需从 raw_track 重建统计产物。旧页面匹配回退因此继续保留。
