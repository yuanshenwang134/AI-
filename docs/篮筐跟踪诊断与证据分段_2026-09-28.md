## #2：记录完整候选与实际跟踪筐

新任务 raw_track.json → detections_meta.legacy_shots 增加 trace_schema=2。

每帧新增：

- rim_candidates：进入旧引擎的所有篮筐候选，每个包含 index、cls、conf、xyxy、track_id、predicted、selection_reason、tracker_reason。这里的“所有”限检测器置信度阈值和 NMS 之后的输出，不包含检测器已过滤的框。
- selection_reason：selected / low_confidence / invalid_shape / not_nearest_hint / outside_center_lock / not_selected / manual_override。
- tracker_reason：选中框被跟踪器处理的结果，或 not_submitted。跟踪器结果包含 pending_confirmation、initialized、tracked、jump_rejected、identity_wait、scale_rejected、no_candidate、reacquired_near、reacquired_far。
- selected_rim_source：detector / manual / none。原 rim 保留为送入跟踪器的框，不冒充实际使用的筐。
- tracked_rim：平滑后的 cx/cy/w/h、fresh、last_seen_t、segment。未初始化为 null；失效位置仍可追溯，但 fresh=false，不用于新判定。
- hint_relation：提示点距当前跟踪框中心的像素距离、是否在框内。仅几何关系，不能证明目标正确。
- center_rejected_candidates：本帧因中心约束被拒的候选数，区别于帧数。
- evidence_segment：本帧普通事件所在证据段；重新确认时收尾的 unknown 仍指向旧段。

汇总 rim_tracking 包含 first_confirmed、last_tracked、transitions、拒绝候选数/涉及帧数、提示点与中心锁参数。

game.json → meta.shot_engine_details 只附加精简 rim_tracking 和 trace_schema，不复制全部逐帧数组。scripts/legacy_trace_summary.py 已兼容新旧格式，旧 trace 的实际跟踪位置不可恢复时明确显示 None，不再把选中框当实际筐。

## #4：证据分段

RimTracker 增加 generation 和 last_update_reason。首次确认建立一个跟踪段，失效后确认新位置建立新段；平滑移动不会新建身份。ScoreEngine 以有效的新 generation 为边界，把旧未决出手收尾为 unknown，清空 recent_real/history/ball_hist 和旧去重状态；切镜也结束旧段并重建引擎。

这一防护原先已有“失效后变新鲜”触发，本轮改为明确的跟踪代次触发并补齐诊断和回归。不会宣称“已经辨认出两个物理篮筐”。同一物理筐丢失后也可能重建，未过期时渐进式错跟仍可能漏过；真正的物理身份关联与相机运动补偿尚未实现。
