## 三、发现的问题（按严重度）

1. **门禁红灯**（见 2.1）：`web/_test.js` 需要 `await`。这是本轮唯一必须修的点。
2. **timeline 的 `made` 对"结果未知"是 `false`**：`rules.py:360` 用 `made=bool(made)`，
   所以未知被写成 `false`，只能靠 `result="unknown"` 或 `outcome_unknown` 标签区分。
   任何直接读 `made` 的下游（导出、图表、别处的批量逻辑）都会把"未知"当成"未中" ——
   这正是他们自己在批量里防的那个坑。建议 `_shot_event` 直接输出 `made: null`
   （它已经有 `result` 字段做区分），或显式加 `outcome_unknown: true`，并检查下游消费者。
3. **`value=9` 返回 200**：`api.py:763` 只接受 1/2/3，越界值被**静默忽略**但接口报成功。
   这属于"坏请求看起来像成功了"。建议返回 400。
4. `review.js:143`：`row._index` 非法时**静默 return**（无任何提示）。
   真实页面里 `_index` 由 `init()` 赋值，正常都有；但万一某条 needs_review 匹配不上 timeline
   （`findIndex` 返回 -1），用户点"确认"会毫无反应。建议给一句提示。
5. 未验证项（如实说明）：我没有在**界面**上点过按钮（他们的 7 项 JS 检查覆盖了这些行为，
   我复核的是数据层与代码路径）；`confirmAll` 批量确认建议的 UI 流程未单独跑。
