## 一、缺陷 A：两次真实出手被合并成一条（收尾靠超时）

被合并的那条事件（产物原文）：

```
{"type":"uncertain","t":13.51,"release_t":10.01,"flight_s":3.5,"real_obs":48,
 "entered":true,"crossing_t":null,"evidence":"insufficient_evidence",
 "rim_xy":[1048.1,238.3]}
```

逐帧依据显示的过程：

```
10.41~10.51  球到筐附近（hd=42→2.8px，筐心距 63→24px）      ← 第一次真实出手到位
10.81~10.91  预测，球落到筐下（y 227→242）
11.01~11.21  连续 0.2s 无球
11.31        球(1008.5,271.1) 真实，已在筐底以下             ← 篮板/下落
11.51~12.11  连续 0.6s 完全没有球检测（7 个采样点）
12.21~13.11  球(915.7,288.9)→(1049.7,181.6)→(938.2,284.6)   ← 第二次真实出手（完整弧线）
13.21~13.51  无球 → 事件收尾
```

**为什么会被合并**：出手的"离开/收尾"判据是
`left_region = hd > 1.6 × max(approach_radius_ratio × 筐宽, 30)`，
也就是 **hd 要超过约 760px**（1.6×5×95）——而筐本身只有 ~95px 宽。
整段 10.0~13.5 秒里，球到筐心的**横向距离从未超过 760px**（篮下连续起跳/争抢），
所以 `left_region` 一次都没成立，上一条出手**只能等 3.5 秒超时**（`miss_timeout_s`）收尾：
10.01 + 3.5 = **13.51** ✓ 正好是产物里的收尾时刻。

后果：12.25s 的第二次真实出手没有自己的事件，被算进上一条里 →
`real_obs=48`、`entered=true`、`crossing=null` → 收尾为 `uncertain`。

**可用的材料**：引擎已经有 `at.rim_rebound_seen`（球在筐口附近下落后又上升），
但当前只用在实验开关 `make_window_from_crossing` 里，没有用在"关掉上一条出手"上。

## 二、缺陷 B：真实进球被记成未中，且离手时间偏晚 1.1 秒

那条事件（产物原文）：

```
{"type":"miss","t":17.08,"release_t":16.28,"flight_s":0.8,"real_obs":4,
 "entered":true,"crossing_t":16.316,"evidence":"left_region_or_timeout"}
```

全量插桩回放的内部状态（与产物一致）：

```
16.28 球(723.2,683.8) 真实  距筐心 550px（离开半径 274px）
      → 此刻【没有未决出手】且 needs_leave=True（上一条 13.51 收尾后要求"球先离开筐区"）
      → 这个【远离篮筐的检测】反而满足了"已离开"，于是【在这里建立了新出手】
      → release_t=16.28（目视：真实离手约 15.1~15.2s）
16.32 同一物体的第二个真实观测 → 与上一条真实观测(15.95, cy=226.6)形成"跨筐心高度"的插值
      → 插值横坐标 1044 恰落在筐口内 → 凭空得到 crossing_t=16.32
16.35~16.48 预测帧沿【假物体】继续（速度估计被污染）
16.52 真实球从网里出来 (1043.1,287.6)：hd=1.3px、筐底以下 ✓
      → 但命中判据要求"当前 cy > 上一条真实观测的 cy"（正在下降）
      → prev_cy=683.6（那个假物体）→ 287.6 > 683.6 = False → 【命中被否】
17.08 远下方真实观测(1205.5,719.8) → left_streak≥2 → 收尾为 miss
      （预测帧在 16.68 已飞到 y=-42，说明速度估计也已被污染）
```

**三条根因**（都可独立修）：

1. **`needs_leave` 的"离开半径"（3×筐宽≈274px）不该由单帧远距离检测清除**：
   篮下连续争夺时球很难离开，而一个**假检测**反倒轻松满足 → 出手被建在一个错误的位置/时刻上
   （`release_t=16.28` 因此偏晚）。
2. **跳变闸门是按帧间隔等比放大的**：`ball_jump_px_per_frame=90px`，
   而 15.95→16.28 间隔约 10 帧 → 允许 900px，于是 550px 的假跳变通过了，
   并且污染了速度估计（后续预测帧沿假物体飞走）。
3. **"正在下降"判据没有时间/连续性检查**：它直接拿 `at.last_real_cy` 比，
   而这个值可能来自很久以前、且可能是假检测（`ball_recent_s` 只用在 crossing 上，
   没用在"下降"上）→ 一条陈旧观测就能否掉真进球。

## 三、结论与优先级（不据本素材调半径）

1. **中心锁定 4→2 不能算改善**：被它过滤掉的区间里包含真实投篮与一次真实进球
   （目视复核：9.75–10.0、12.25、15.0–15.25 三次真实出手，其中最后一条 16.25–16.4 穿网、
   比分 33→35）。**保持默认关闭，不据本素材收紧半径。**
2. 优先级应改成：**出手切分（连续篮板/二次进攻）→ 离手时间与结果关联 → 假检测抑制**，
   而不是继续调中心锁定。
3. 三条判据的**具体位置**（供队友改）：
   - 收尾/离开判据：`scorer.py` 里 `left_region`（`1.6 × approach_r`）与 `needs_leave` 的清零条件；
   - 跳变闸门：`stream.py` 里 `ball_jump_px_per_frame * delta` 的等比逻辑；
   - 命中判据：`scorer.py` 里 `prev_cy is not None and by > prev_cy` 这一条（缺时间窗/连续性）。
4. 上面三条**都不是本机验证过的修法**，只是"证据指向哪里"；改完要用
   nathan / fixedcam / dairy / day / night 五段 + 本段（有目视结论）做整段回归。
