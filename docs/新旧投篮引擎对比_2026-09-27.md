# 新旧投篮引擎对比与本轮修正

## 决策

以旧版的逐次出手状态机作为下一轮投篮引擎基线，吸收新版的证据分级、未知口径与复核契约。保留新版应用及复盘页面，不整体回滚应用，也不把旧引擎未经完整视频回归就设成新版默认路径。

用户认为旧版更好，在已经保存的固定机位/罚球开发素材上有具体证据支持；没有证据证明新版远远好于旧版。旧版也不等于已经能可靠分析完整比赛。

## 比较对象和证据边界

- 原始旧版专题存档：`D:/dsh_folder/hoopai_投篮检测_旧版`，本轮未改。
- 完整恢复工程：`D:/dsh_folder/_tmp/hoopai_from_bundle`。本轮修正在这里，Git 中可看差异。
- 新版应用：`D:/dsh_folder/aihoop`。本轮未改其检测默认路径。
- 历史证据：旧版 `eval/product_model_switch_runs.json`、`eval/product_model_switch_pairs.md`；新版 `out/eval_after_ballclear.json`、`out/eval_after_hoopmark.json`、`out/eval_fixedcam_recheck.json`。
- 本轮做了代码核对、权重哈希、合成检测输入自对照与针对性测试，没有重新跑 GPU 视频推理。历史产物不是同一配置、同一时间的严格 A/B。
- 旧版顺序标签一致，不等于有逐球时间戳的独立评测；dairy、fixedcam、nathan 均进入过 v6 训练集。不能据此报告通用准确率。

## 最关键发现：模型其实相同

以下三份文件的完整 SHA256 均为：

`800dab7c265b4cf9e488f75eb293f659f34a6efa86300c4823563887329072d9`

- 旧版 `models/rim_ball_v6.pt`
- 新版 `runs/detect/ball/weights/best.pt`
- 新版 `runs/detect/rim/weights/best.pt`

新版 API 默认优先使用后两份路径。因此当前默认权重文件并不是新的两个独立训练模型，而是同一旧版权重的副本。显式指定权重的历史任务仍需逐任务核对。模型文件相同也不意味着输入尺寸、抽帧、候选筛选和输出相同。

## 优缺点与代码依据

| 方面 | 旧版 | 新版 |
|---|---|---|
| 出手覆盖 | 状态机先建立候选，再判进/未中/未知，固定机位历史结果更完整 | `sources.py` 先跑 hoopsight，只有完全没有 attempts 才跑球轨迹判定；后续虽有 extract_attempts，但保存结果已证明并未补全固定机位漏项 |
| 连续性 | 短时预测维持轨迹、离开筐区后解锁下一次出手、丢球/片尾收尾 | 长轨迹切弧线，片段质量和筛选更复杂；有重复候选和漏段问题 |
| 篮筐跟踪 | 连续确认、EMA、过期重捕；身份锁是可选项，默认关闭 | 有身份连续性筛选和漂移闸门，可能整段拒绝，移动镜头召回差 |
| 命中可靠性 | 有向下穿越、出口、时窗、回弹检查，但二维前后掠过仍可能误判 | 有净空/局部不确定度/实测与推算分级，错误可解释性较好，但更保守不等于总体更准确 |
| 未中可靠性 | 离区、落得很低或超时可判未中；并非所有“未中”都有明确未进证据 | unknown 契约、建议不计分、人工确认和导出更成熟 |
| 比赛适应 | 靠近篮筐就可建立出手，传球可能混入；离筐解锁也可能漏近筐补篮 | 多路径与多人/摇镜过滤较多，存在“干脆没有事件”的体验问题 |

旧版 README 中“0.65×半径”和“新版没有身份跟踪”等描述不能直接当事实：旧版代码中 `rim.w` 是整宽；真实穿越交点限制为 `rim.w / 2`；0.65 出口限制仅 strict_shot_gate 开启时生效，默认关闭。新版已存在身份筛选，因此不是从零缺失。

不直接移植新版 0.467 净空阈值：它是保守二维近似，不是三维碰筐定理；既有人工确认进球也有较大偏移。应保留多种证据，不能拿一道横向阈值解决所有情况。

## 已实施的小范围改进（完整旧版工程）

1. `engine/scorer.py`：只有真实观测才可建立新出手。预测点仍可推进已有候选，不能凭空造候选。
   - 同一合成输入自对照：原版生成 1 条 uncertain，real_obs=0；修正版 0 条。
2. 遮挡备用开关默认仍关。显式打开时，仅凭遮挡入口+出口推断的候选改为 uncertain，suggested_made=true，points=0。实测向下穿越路径保持原判据。
3. 事件新增 result/made/needs_review/suggested_made/review_reason/evidence_grade/crossing_t。未知 made=null，保留原 type/evidence/rim_crossing_t 字段兼容旧消费者。旧前端尚未专门展示新增建议字段，原 uncertain 会作为未知显示。
4. 新增 `tools/test_evidence_contract.py`，更新遮挡实验测试预期。

验证：新增证据契约 5 项、原穿筐几何 12 项、重捕获 5 项，共 22 项通过。不是 GPU 回归，不据此宣称历史 7/3 或 6/5 已在修正版重现。

## 下一轮外部视频验收

比较三路：原始旧版、修正版旧版、新版。采用相同视频文件、原分辨率/帧率、记录模型哈希与完整配置。固定机位优先检查 7 条是否仍为 3 中4未中；nathan 检查 6 条和第一球假进负例。再加比赛传球、扣篮、日夜室外，统计漏出手、重复、错进、未知和判定时刻。

原始旧版不要用已经修过的完整恢复工程冒充：基线可取 Git 原 HEAD 或专题存档 scorer；修正版用当前工作区。禁止把不同运行的球轨迹和筐轨迹拼接作同输入对照。

本轮不要求重新框球/筐。当前缺的是修改后完整视频对照与比赛逐球真值，不是再多加几个未经验证的阈值。
