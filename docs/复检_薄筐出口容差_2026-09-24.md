## 二、我上一轮那条建议是错的（先认错）

我建议把出口判据从「`gy >= 1.0`（ry 的倍数）」改成「绝对像素下限 `max(ry, 4~6px)`」——
**方向搞反了**：那是把要求**提高**（薄筐上原本只要 3.9px，改成要 4~6px），
那 0.16px 的短缺会更过不去。你们指出并拒绝了这条，是对的。

正确的方向只能是二选一：**(a) 允许一个很小的向下容差**，或 **(b) 改用篮圈中心线判据**。
你们选了 (a)，并且加了上限（≤0.5px 且 ≤0.1×ry）、把横向收紧到 0.6×rx、
仍然要求过完整几何判据 —— 这个组合是稳的。

### 3.4 这次修改的"安全边界"我能验证到什么程度

* **可关**：`exit_pixel_tolerance=0.5`，设 0 即回原规则；效果差异在同一份 trace 上只有 1 条。
* **范围窄**：只在筐心区（`|gx| ≤ 0.6×rx`）生效，且容差 ≤ 0.5px 且 ≤ 0.1×ry。
* **不替代证据**：仍然要过 `_judge_span`（筐内证据帧、下落距离、回弹否决）。
* **没验到的**：只有 `fixedcam` / `dairy` 两段素材走了这条路径（其它两段一个走球+筐、
  一个在更早的闸门就放弃），所以「容差会不会把擦筐而过的球收进来」这件事，
  **在其它机位/素材上仍然没有独立验证**。曾被你点名的 `nybo_3min` 那两个假进球、
  以及任何新机位，都建议用本轮新增的 trace + 回放脚本再跑一次对照。
