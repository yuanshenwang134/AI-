## 新增逐帧候选诊断

篮下扫描结果的 `detections_meta.hoopsight.candidate_trace` 现在包含：

- frames：原视频秒数、帧号、篮筐编号、窗口、当前篮筐位置、连通域数量、面积阈值、各筛选原因数量、选中块。
- stage：empty_window / frame_shape_mismatch / no_motion_components / all_components_filtered / low_small_blob_rejected / selected。
- spans：有块后的时序诊断，包括 no_entry_in_band、no_exit_in_band、candidate_gap、exit_timeout，以及证据帧不足、回升、下落不足、穿越偏出、筐内证据不足等。
- counts：原因累计计数。geometry_passed 只代表几何通过，最终置信度剔除仍看既有 rejected。
- frames 与 spans 各最多保存 30000 条，超出部分计入 truncated / spans_truncated；累计计数仍继续。没有条目不等于没扫描，应先核对截断信息。

这些记录解释的是算法哪一关没有通过，不自动证明该时刻是真实投篮、漏检还是传球。没有稳定篮筐而提前放弃时仍以 hoopsight_error / skipped 原因为准。

读取指定时间附近的记录（不运行检测）：
```
python scripts/explain_shot_gap.py --raw out/JOB/raw_track.json --at 9.14 --span 2
```
旧产物没有记录时明确报缺失，不能从旧 blobs 总数补造失败原因。需要复检方用新版重跑后才能定位 dairy/fixedcam 的漏球。

## 服务重启任务恢复

新任务创建时记录本机名、执行进程 PID 和进程创建时间。启动恢复仅把确认进程已退出或 PID 被复用的 queued/running 任务标为 error，message 为任务已中断，error 为 worker_process_exited。正常完成任务和仍存活任务不受影响。保留原进度与产物，不自动重复提交。

休眠、推理耗时长均不作为中断证据；跨机器、权限不足、缺少 psutil 或旧任务缺少进程身份时不猜测失效。旧任务显示历史状态待确认，仍需核实后重新分析。该实现没有自动清除所有历史 running，也不是后台定时清理。
