# 把"发现出手"与"判断进没进"分开：原型与结论（2026-09-29）

> 复核方给的方向：**先结合离手动作、球的上升轨迹发现候选出手；有穿筐证据再判进，
> 证据不足就标未知并给时间点；抬手/传球也可能相似，不能直接算投篮，要保留候选复核。**
> 本文用**已录的逐帧依据**把这条路原型化，量出「能补回多少 / 上限在哪 / 会多出多少候选」。
> **不重跑视频、不改产品代码、不改判定**。

## 一、结论先说

| 问题 | 这一次量出来的答案 |
|---|---|
| 只靠球轨迹能不能发现出手 | **能**，前提是球被跟踪到：day 真值 3 球**全部发现且时间差 0.06~0.28 秒**；fixedcam 候选数 7 = 真值 7 次投篮 |
| 能不能补回现在漏掉的 | 能补回**时间**：day 第 1 球真值出手 6.9s，当前引擎报 8.24s，轨迹发现给 **7.74s**；night 的 5 球里 3 球有落在 ±1.5s 内的候选 |
| 上限在哪 | **球可见性**。night 有 2 球的窗口里"根本没看到球上升"（一个 25 帧、一个只有 2 帧）→ **任何方法都发现不了**；这类时段必须说"没看到"，不能说"没有出手" |
| 代价是什么 | 候选会明显多于真值：**day 10 个候选里 7 个没有被真值占用**、night 9 个里 7 个、dairy 3 次出手出 6 个候选 → **必须走候选复核，不能自动算投篮** |

## 二、原型规则（以及我踩的两个坑，直接写出来省得再踩）

规则本体（只用**真实观测**的球，不用预测点）：

1. 在 ±0.6 秒的滚动窗口里找**局部顶点**（y 最小＝最高点）；
2. 顶点前上升 ≥ 25px、顶点后下落 ≥ 12px；
3. **该段轨迹曾经接近过篮筐**（到筐心距离 ≤ 3×筐宽）；
4. 去重：1.2 秒内只留上升最高的那个。

**坑 1：不能"按缺口切段、每段只找一个顶点"。**
v0 这么写，nathan 只出 **2** 个候选（有一段 312 帧 / 7 秒被球连续跟踪，整段塌成一个顶点），
fixedcam 出 **0** 个。改成滚动窗口后 nathan **8** 个、fixedcam **7** 个。

**坑 2：判据必须是"轨迹接近过篮筐"，不是"顶点接近篮筐"。**
v1 要求顶点离筐 ≤3 筐宽，fixedcam **0** 个候选通过；查下去发现它 7 个弧线的上升 141~174px、
下落 75~109px 全都成立，只是**顶点离筐心 190~212px 而筐宽只有 51px** —— 跳投的顶点本来就在筐上方很远处。
把判据换成"整段轨迹到筐心的最小距离 ≤3 筐宽"后，fixedcam 立刻得到 **7** 个候选，且时刻
（0.83 / 4.4 / 7.63 / 11.03 / 14.77 / 18.07 / 21.4）与"7 次投篮"的素材完全对得上。

## 四、四条可落地的结论

1. **发现层与判定层分开是对的，而且发现层可以只吃球轨迹。**
   day 的 3 球时间差 0.06~0.28 秒；对比当前引擎在 day 第 1 球把出手报成 8.24s（真值 6.9s）——
   发现层解决的是"**有没有出手、什么时候出手**"，判定层继续只管"进没进"。

2. **候选明显多于真值，必须复核，不能自动计分。**
   day 7/10、night 7/9、dairy 3 个额外。这些候选里有多少是真实投篮、多少是传球/运球，**要画面才能定**
   （我看不到图）。产品侧的做法应当是：候选进列表、标"待复核"，确认前不进统计 —— 与刚做的
   "疑似命中建议"完全同构。

3. **"贴筐起跳的弧线"是一类可识别的误报源。**
   把每个候选**弧线起点到筐心的距离**按筐宽归一后：
   - `fixedcam` 7 个候选全是 **8.1~8.6 筐宽**（罚球线附近的固定投篮点，非常整齐）；
   - `dairy` 的 3 个额外候选起点是 **2.9 / 3.8 / 3.8 筐宽**，正好落在"上一次出手之后约 2 秒"——
     符合"打铁反弹/抢板后二次起球"的形态；`nathan` 的 2 个额外候选同样是 **2.9 / 3.0 筐宽**。
   → 建议：**起点离筐 < ~3.5 筐宽的候选单独成一类**（近筐类：补篮/二次进攻/反弹球），
   给更低置信、要求额外证据（离手动作或前一次判罚已结束）。
   注意**不能直接删**：day 第 3 球真值就是"上篮/补篮"，起点必然贴筐。

4. **上限由球可见性决定，产品要把"没看到"说清楚。**
   night 5 球里 2 球窗口内根本没看到球（其中一球仅 2 帧）；
   另一段 `night` 的可用筐也只有 23%。所以除了已有的"可用篮筐时段"提示，
   还需要一个平行的**"球可见性"摘要**（每段真实球观测帧占比 + 最长缺口），
   界面上区分"没有出手"与"这段没看到球"。

## 五、给实现方的建议（我没写产品代码，只给接口与口径）

1. **新增独立前置层 `discover_candidates`**：输入球轨迹（+ 可选人物框/离手动作），
   输出 `candidate_attempts`：`release_t`、弧线顶点、起点距筐、上升/下落幅度、
   观测帧数、是否"上升后消失"、置信依据。**不改判定层**。
2. **判定层按原样消费候选**：有实测穿筐 → 命中；有"局部遮挡 + 筐内连续下降" → 建议；
   其余 → 未知 + 时间点（复用现有 `suggested_made` / `review_t` / 复核页）。
3. **产物加 `candidates` 列表**（含上面那些字段）与复核入口；旧任务需重建产物。
4. **加"球可见性"摘要**（与 `rim_tracking.availability` 平行），并在空结果时说明原因。
5. **回归口径就用本文的指标**（可直接跑 `_tmp\prototype_shot_discovery.py`）：
   真值唯一命中数（Δ≤1.5s）、近似数、未被占用候选数。当前基线：
   day 3 / 0 / 7；night 3（含共用，独立 2）/ 2 / 7；fixedcam 候选 7；nathan 8；dairy 6。

## 六、边界（不夸大）

- 原型只用了**已录的逐帧依据**（不是重新推理），参数（RISE_MIN=25px、±0.6s 窗口、3 筐宽等）
  是我按这 5 段调的，**没有做过独立素材验证**；
- `fixedcam / nathan / dairy` 只有**顺序真值**（没有时刻），所以只能比数量、不能逐球核时间；
  能逐球核的只有 `day`（3 球）和 `night`（5 球）；
- "多出来的候选是传球/运球还是被真值漏掉的投篮"**需要画面复核**，我这边看不到图；
- 本轮没有改任何产品代码、判定或默认值。
