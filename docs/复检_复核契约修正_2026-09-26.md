## 三、还剩下的一处（代码级发现，非本轮引入）

`made` 变成 `null` 之后，**还有几处只看 `made` 不看 `result`**，会把"未知"渲染成"未中"：

| 位置 | 现在会发生什么 |
| --- | --- |
| `web/data.js:194` / `:206`（`made: !!s.made`） | 未知出手的 `made` 被压成 `false` |
| `web/court.js:276` / `:288-295` | 投篮图/热区按 `p.made` 上色 → 未知的球画成**红色（不中）** |
| `web/overview.js:369` | 时间轴徽章 `:class="e.made?'made':'miss'"` → 文字对（"待确认"），**颜色是不中** |
| `web/pages/review.js:395` | 补录弹窗的默认文案按 `made` 判断 → 对未知行会默认显示"未中" |

已经处理正确的地方（供对照）：`review.js:118` 的 `isUnknown`、`overview.js:163-164` 的筛选、
`highlights.js:272` 的文案、CSV、以及 `data.js:109` 的算分（unknown 计 0 分）。

建议：把 `made: !!s.made` 改成 `made: (s.result === 'unknown' || s.made == null) ? null : !!s.made`，
并给未知单独一个中性配色/样式（例如空心灰点），避免"未知=不中"的误读 —— 这与产品一直强调的
"别用 0 分掩盖失败"是同一件事。

说明：这条我**只在代码层核对**，没能在运行时演示 —— 我用真实任务（nathan）取投篮图时
点位是 0 个（那次跑没有球场标定，出不了球场坐标），所以看不到红点。有一段带标定的素材就能直接复现。
