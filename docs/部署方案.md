# 部署方案（aihoop 真视频链路）

> 写于 2026-09-23。**部署的第一分叉点不是 Docker，而是"比分牌 OCR 依赖 Windows"** —— 见第 1 节。
> 标 **[已验证]** 的是我在本机实测过的；标 **[未验证]** 的是必须在你服务器上跑一次才算数的。

---

## 1. 先定路线：服务器是 Windows 还是 Linux？（硬约束）

比分牌识别有**两条路**，成熟度完全不同：

| 路径 | 实现 | 平台要求 | 实测表现 |
|---|---|---|---|
| **手动框选/自动定位 + OCR** | `scripts/ocr_batch.ps1`（Windows.Media.Ocr，经 PowerShell + WinRT）+ `src/aihoop/ocr_scoreboard.py:36 _powershell()`、`:45 sys.platform.startswith("win")` | **仅 Windows** | **[已验证]** 校园转播素材读到 38:38、10 条事件，与人工逐帧核查一致 |
| 模板匹配 | `src/aihoop/scoreboard.py` | 跨平台 | **[已验证]** 非标准台标（校园/村 BA 横条）**一帧都读不出**（`frames_hit=0`） |

**结论**：
- 服务器是 **Windows** → 当前代码原样可跑，OCR 路径可用（但要先过第 1.1 的体检）。
- 服务器是 **Linux/容器** → **比分牌这条路直接失效**，只剩模板匹配（对这类素材等于没有）。
  此时必须二选一：① 换 OCR 引擎（tesseract / PaddleOCR，需改 `ocr_scoreboard.py` 的 `_powershell()` 分支并重做 `ocr_batch.ps1` 的等价实现）；
  ② 接受"Linux 上只能跑靠球+筐检测的视觉计分"（准确率会明显下降）。

### 1.1 Windows 服务器也要先体检：Server SKU 常常**没有** OCR 引擎
`Windows.Media.Ocr` 属于客户端媒体组件，**Windows Server 默认可能不带语言/媒体包**（Server Core 基本没有）。
在目标服务器上跑这一句，能列出识别语言才算可用：

```powershell
[Windows.Media.Ocr.OcrEngine, Windows.Foundation, ContentType = WindowsRuntime] | Out-Null
[Windows.Media.Ocr.OcrEngine]::AvailableRecognizerLanguages
```
- 有输出（如 `en-US`）→ OCR 路径可用。
- 报错或空 → 换成 Windows 10/11 客户端机，或按第 1 节换引擎。

## 2. 三种部署形态（按场景选，别一上来就上 K8s）

| 形态 | 适用 | 组件 | 成本 |
|---|---|---|---|
| **A. 单机直跑**（推荐先做） | 答辩现场、内网演示 | 后端 `uvicorn` + 一个静态文件服务 | 最低，少一层故障（作者文档也是这个建议） |
| **B. Windows 机器常驻** | 实验室/内网长期用，素材是校园转播 | A + 注册成服务 + 反向代理（鉴权） | 中 |
| **C. Linux + GPU 容器** | 公网/云主机、要跑真视频推理 | nginx + api 容器 + GPU 直通 + 换 OCR 引擎 | 最高，且必须改代码（第 1 节） |

### 形态 A：单机直跑（Windows，最省事）

```powershell
# 1) 依赖（本项目不用 venv，依赖装进项目内目录或直接用系统 Python）
pip install -r requirements.txt
pip install -r requirements-full.txt      # 真视频推理才需要（torch/ultralytics/opencv）

# 2) 后端（自带源码改动自动重启）
powershell -ExecutionPolicy Bypass -File .\run_backend_local.ps1 8000
#   若依赖是 pip 全局安装的，也可以用他自带的：.\启动后端.bat

# 3) 前端静态服务（浏览器不能直接开 file://，会被拦截读本地 JSON）
python -m http.server 8080 --bind 127.0.0.1

# 4) 打开
#   前端 http://127.0.0.1:8080/web/index.html
#   接口 http://127.0.0.1:8000/docs
```
**[已验证]** 这三步在本机跑通：后端 `/api/health` 200、前端 200、合成 demo 可出结果。

### 形态 B：Windows 机器常驻（内网多人用）

1. **注册服务**（二选一）：
   - `nssm install aihoop-api "C:\...\python.exe" "-m uvicorn aihoop.api:app --host 0.0.0.0 --port 8000"`，工作目录设为仓库根，环境变量加 `PYTHONPATH=<repo>\src`；
   - 或任务计划程序：开机启动 + "无论用户是否登录都运行"。
2. **反向代理 + 鉴权**（当前**没有任何登录**，见第 4 节）：IIS + ARR，或 nginx for Windows：

```nginx
server {
    listen 80;
    client_max_body_size 2g;                 # 上传是一整个视频，默认 1m 会直接 413
    proxy_read_timeout 3600s;                # 分析任务跑几分钟，别让代理掐断
    proxy_send_timeout 3600s;
    auth_basic "aihoop";
    auth_basic_user_file C:/nginx/conf/.htpasswd;

    location /api/ { proxy_pass http://127.0.0.1:8000; }
    location /     { root C:/aihoop/web; try_files /index.html =404; }
}
```
3. **数据放在哪**：`data/`（视频、标定、任务库 `jobs.sqlite`）与 `out/`（分析产物）在仓库目录下，**要单独放到数据盘**并纳入备份。

### 形态 C：Linux + GPU 容器

仓库自带的 `Dockerfile` / `docker-compose.yml` **[已验证内容]** 是"套餐 A 最小镜像"：
`python:3.11-slim` + `ffmpeg` + `requirements.txt`（**不含 torch/ultralytics/opencv**），
所以它**只能跑合成 demo 与 API**；真视频推理要自己加深。要改三处：

```dockerfile
# 在自带 Dockerfile 的 pip install 之后追加（GPU 机器按 pytorch.org 指引换成 CUDA 版索引）
RUN pip install --no-cache-dir opencv-python-headless ultralytics
RUN pip install --no-cache-dir torch --index-url https://download.pytorch.org/whl/cu126
```

```yaml
# docker-compose.override.yml
services:
  api:
    environment:
      - NVIDIA_VISIBLE_DEVICES=all
      - YOLO_CONFIG_DIR=/app/data/_ulcfg     # 否则 Ultralytics 会去写 HOME 被拒（本机踩过）
    deploy:
      resources:
        reservations:
          devices: [{ capabilities: [gpu] }]
    shm_size: "2gb"
```

```powershell
# 服务器上（我本机没装 docker，故这些都是[未验证]）
docker compose build
docker compose up -d
docker compose exec api python -m aihoop.cli demo --seed 7 --duration 300 --out out/demo   # 先证明镜像自洽
curl -s http://127.0.0.1:8000/api/health
```

**镜像体积预期**：仅最小依赖约 300–500MB；加上 torch（CUDA 版本机实测 4.0GB）+ opencv(112MB) + numpy(31MB) 后 **约 6–8GB**，`docker pull`/构建要给足时间和磁盘。

## 3. 部署前置清单（缺一样就翻车）

| 项 | 要求 | 依据 |
|---|---|---|
| **ffmpeg** | 在 PATH 里；Dockerfile 已装 | 高光剪辑用；本机 `_ffmpeg()` 走 PATH |
| **权重** | `runs/detect/ball/weights/best.pt` 与 `runs/detect/rim/weights/best.pt`（或 `data/shot_tracker_best.pt`）；也支持 `AIHOOP_MODELS` 环境变量指向目录 | `.gitignore` 排除了权重，**仓库里没有，必须手工放到服务器**；本机已用自训练的 `rim_ball_v6.pt`（basketball=0/rim=1，sha256 `800DAB7C265B4CF9…`）验证可用：球帧覆盖 65.3%、筐帧 73.1% |
| **GPU** | 真视频推理建议有；CPU 能跑但慢十几倍 | 作者 README；本机 720 帧抽样检测耗时 136s（RTX 4060 Laptop） |
| **磁盘** | 按"并发 2 × 单任务体积"预留，建议 ≥50GB 并配清理策略 | **[已验证]** 只读比分任务 2–25MB/个；完整分析（含标注视频+高光）旧管线实测 100–350MB/个；上传的原始视频另计 |
| **并发** | 只能 **单实例**；进程内 `ThreadPoolExecutor(max_workers=2)`（`api.py:52`），任务表是 SQLite | 起多副本会争抢 SQLite 与 `out/` 目录 |
| **端口** | 后端 8000、静态 8080（或任意）；对外只暴露反向代理的 80/443 | |
| **环境变量** | `PYTHONPATH=<repo>/src`、`YOLO_CONFIG_DIR`、`TMP/TEMP`（Windows 上还要 `PYTHONIOENCODING=utf-8`） | 缺 `YOLO_CONFIG_DIR` 会报 `[WinError 5] ...AppData\Roaming\Ultralytics`（本机踩过） |
| **数据备份** | `data/jobs.sqlite`、`data/*.json`（标定/篮筐标点/比分事件）、`out/*/game.json` | 分析产物可重跑，标定与事件是人工投入 |

## 4. 暴露到公网之前必须补的东西（现在是零防护）

| 风险 | 现状 | 最低限度处理 |
|---|---|---|
| **无鉴权** | 没有任何登录/令牌 | 反向代理 `auth_basic` 或限制内网 IP |
| **CORS 全开** | `allow_origins=["*"]`（`api.py:48`） | 上线时收紧为前端域名 |
| **上传无限制** | `/api/upload` 流式写盘，**不限大小、不限类型**（`api.py:2187`） | 反代 `client_max_body_size` + 磁盘配额 |
| **无速率限制** | 谁都能反复提交任务 | 反代 limit_req，或加简单令牌 |
| **任务产物直出** | `/api/media`、`/api/games/{id}/video` 无鉴权即可下载 | 与上同（走同一层鉴权） |

## 5. 上线自检（在服务器上依次跑，全绿才算部署成功）

```powershell
# ① 后端活着，且依赖齐全
curl http://127.0.0.1:8000/api/health
#   期望：{"ok":true,"ffmpeg":true,"ultralytics":true,"opencv":true,...,"stale":false}

# ② 零依赖路径能跑（不联网、不需要权重/视频）
python -m aihoop.cli demo --seed 7 --duration 300 --out out/demo
#   期望：打印比分/出手数，out/demo 下出现 game.json / report.md / tactics.json

# ③ 前端能打开
#   浏览器访问 http://<服务器>:8080/web/index.html，切"演示数据"能出图

# ④ 真视频链路（需要权重 + 一段视频 + 标定）
python -m aihoop.cli video --video <视频> --cal <标定.json> --out out/test1
#   期望：status=ok；有标定时才会出位置类结论

# ⑤ 比分牌 OCR 路径（**只在 Windows 且第 1.1 体检通过时**）
#   界面"上传 → 读比分牌"，或：
curl -X POST http://127.0.0.1:8000/api/scoreboard/ocr -H "Content-Type: application/json" `
     -d "{\"video_path\":\"<视频绝对路径>\"}"
#   期望：final 与画面一致；note 里给出"读数覆盖 x/y"；若基线被推迟会有 ⚠️ 提示

# ⑥ 全套自检（作者自带）
python scripts/check_all.py      # 期望 11 组全部通过
```

## 6. 我需要你确认的三件事（决定我给你出哪一套现成文件）

1. **服务器是什么系统？** Windows（含 Server 版本与 SKU）还是 Linux？—— 决定第 1 节走哪条路。
2. **有没有 GPU？** 有的话是 NVIDIA 什么型号、驱动/CUDA 版本？—— 决定镜像与 `deploy.resources` 怎么写。
3. **只给内网用，还是要公网可访问？** —— 决定鉴权与限流的强度（现在完全没有鉴权）。

告诉我这三点，我可以直接产出对应的现成文件：
- Windows：`install_service.ps1`（NSSM 注册）+ `nginx.conf` + 上线自检脚本；
- Linux+GPU：`Dockerfile.gpu` + `docker-compose.prod.yml` + `nginx.conf` + `.env.example`；
- 以及一份"把权重/素材/标定搬上服务器"的清单（含 SHA256 校验）。
