# 标定代码准不准：逐项验证与结论（2026-10-03）

用户原话：「我标点就说表的不对，你这个标定的代码真的准确吗」。
这篇把"标定这条链路上每一段到底准不准"逐项验掉，并说明**不准的话不准在哪里**。

## 1. 单应矩阵求解器：**准**（有两条独立证据）

### 证据 A：4 个角点回代，误差为 0

用一组像真实机位的 4 个角点解 H，再把每个角点投回去：

```
[ -80, 150] -> ( -7.500,   0.000)   期望 (-7.5, 0.0)
[ 910, 115] -> (  7.500,   0.000)   期望 (7.5, 0.0)
[ 930, 530] -> (  7.500, -14.000)   期望 (7.5, -14.0)
[ -95, 515] -> ( -7.500, -14.000)   期望 (-7.5, -14.0)
```

（`tests/test_point_diagnosis.py::test_solver_maps_corners_exactly`）

### 证据 B：与 numpy 独立实现**逐元素相同**

另写一份 DLT（Hartley 归一化 + numpy 最小二乘），对同一组点求解，
两个 3×3 矩阵的 9 个数字完全一致（`np.allclose(..., atol=1e-9)`）。
**若是求解器 bug，两边不可能一致。**
（`tests/test_point_diagnosis.py::test_solver_agrees_with_numpy_dlt`）

> ⚠️ 验证过程中我自己踩了一个坑，记下来：我第一版"回代测试"把方向写反了
> （`find_homography(像素, 球场)` 得到的是像素→球场，我却拿它去投球场点），
> 于是打印出 1000+ 像素的假误差，差点误判成求解器有 bug。

## 2. "标的不对"这句话：来自**多点的冗余校验**，不是求解器

单应矩阵 8 个自由度：**给 4 个点必然精确，误差恒为 0**；只有第 5 个点开始才有
冗余、才能发现"某个点跟其余对不上"。所以：

* 4 个点时它永远是"对"的 —— 这个数字不能当质量依据（项目注释里也这么写）；
* ≥5 个点时若报"互相矛盾"，那是**点集内部不自洽**，而不是算错了。

实测用户那 6 个点（从截图读的坐标）：

| 统计 | 值 |
|---|---|
| 6 点整体拟合 | 一个 8 自由度超定系统，残差 ~3.19m（界面报的） |
| leave-one-out：排除「篮筐中心」后它偏 | **33.06 m** |
| 排除「底线左角」后它偏 | 7.91 m |
| **其余点彼此的平均误差** | **1.58 ~ 7.08 m**（无一为 0） |

**关键读数**：把最可疑的点排除后，剩下的点**彼此**还差 1.6m 以上 ——
（正常情况应在厘米级）。这不是"某一个点手抖"，而是**点名与物理位置成片对不上**。
最常见的两种原因：

1. 把某个角当成了另一个角（例如把罚球区角当成底线角）；
2. 把这一侧半场的点，标到了另一侧（两半场关于中线对称，点名的物理含义差 14m）。

## 3. 因为"不说哪个点"太坑，补了逐点责任诊断

`_diagnose_keypoints()`：leave-one-out 交叉验证，逐点给出

* `excused_err_m`：把该点排除、由其余点解出的标定让它偏多少米；
* `others_mean_err_m`：其余点**彼此**的平均误差（判断"是不是单点问题"）。

界面现在会显示：

> 逐点体检：这些点里哪个跟其余对不上
> `篮筐中心：排除它后偏 33.06 m（其余点平均 1.58 m）` …

而且名字用**界面上的那个**（前端传 `{value,label}`），
因为后端把某一侧的篮筐叫「另一端的篮筐中心」，照抄用户对不上自己按的按钮。

## 4. 顺带发现的两个真 bug（都已修）

1. `_diagnose_keypoints` 里 `find_homography` 没导入（`api.py` 里它是函数内局部导入的）
   → 抛 `NameError`，又被我的宽 `except` 吞掉，误报成"点几乎共线"。
   现在异常类型也带进输出，不再吞掉真因。
2. 前端 landmarks 从 `[x,y]` 改成 `{value,label}` 后，后端解析必须同时兼容两种写法
   （已兼容，并加了 `tests/test_point_diagnosis.py` 与
   `_tmp/probe/verify_label_passthrough.py` 双向验证）。

## 5. 结论（一句话版）

**求解器是准的**（两条独立证据）；**"标的不对"是点集内部不一致的真实读数**；
但以前它**不说是哪个点**，这才是让你觉得"软件在乱说"的原因 —— 现在它会点名。
