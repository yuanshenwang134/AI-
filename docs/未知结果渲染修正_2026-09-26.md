## 一、先更正我上一轮的说法

上一轮我说"有四处只看 `made` 不看 `result`，会把未知渲染成未中"。**逐处核代码后，
只有一处成立**，其余三处我判断错了：

| 位置 | 上一轮我的说法 | 实测结论 |
| --- | --- | --- |
| `web/data.js:194` / `:206` | 会把 null 压成 false | **不成立**：`D.shotsFromTimeline` / `D.shotsFromPlayers` 都在入口就 `filter(result !== "unknown")`；后端 `rules.shot_chart` 也过滤了未知（`rules.py:554`）。未知根本进不到这两行 |

## 二、改了什么（2 个文件 + 1 个新测试）

1. **`web/pages/overview.js`**：把徽章配色抽成一个方法，并接进模板：

```js
resultClass: function (e) {
  if (!e) return 'miss';
  if (e.result === 'unknown' || e.made === null || e.made === undefined) return 'needs';
  return e.made ? 'made' : 'miss';
},
```
模板 `:class="e.made?'made':'miss'"` → `:class="resultClass(e)"`。
待确认沿用**既有但一直没被用到的** `.needs` 橙色样式（`styles.css:175`），语义就是
"需要人工复核"，不新增颜色、不动设计系统。

2. **`web/data.js`**：`D.shotLabel` 对 `null`/`undefined` 输出"待确认"而不是"未中"
   （目前只用在投篮图 tooltip，属防御性修改 —— 图表点位本身已排除未知）。

3. **新增 `tests/test_unknown_style.js`（12 项检查）**，并接进 `scripts/check_all.py`
   的前端门禁组（`8d/9`）：
   * 徽章配色三态必须分得开（含 `result=unknown` 但 `made=false` 的边界）；
   * tooltip 文案：`命中两分` / `未中两分` / **`待确认三分`**；
   * 模板确实走 `resultClass(e)`、且不再出现直接按 `e.made` 配色的写法；
   * `.tl-badge.needs` 样式存在（避免"待确认"没颜色）。
