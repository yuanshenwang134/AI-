# 位置未知的出手：导出/报告不再给假距离、假热区（2026-09-28）

对应优先项 1（"修正 shots.csv 假距离，位置未知就导出为空"）。
查的过程发现**同一个 bug 有三个面**，所以三个一起修了。

## 一、问题：同一份产物里，一边说"没有坐标"，一边给出假数据

旧引擎在没有球场标定时，把出手位置写成占位坐标 `(0, -1.575)`（贴着被进攻篮筐），
`rules.build_shots` 会给这类出手打 `location_unknown` 标签。此前的实际情况是：

| 位置 | 修复前 | 修复后 |
|---|---|---|
| `shots.csv` / 网页下载的 CSV | `distance=0.0`、`zone=禁区` | 距离为空、区域"位置未知" |
| `report.json → hot_zones` | `[{"zone":"禁区","att":6,"made":5,"pct":0.833}]` | `[]` |
| `report.json → key_shots` | 占位出手带上"禁区 / 距篮 0.0m" | 事件保留，区域"位置未知"、距离 `null` |
| 网页"报告页"高效出手区域 | 直接渲染 `report.json.hot_zones` → 显示假热区 | 空表 + 常驻说明 |
| 同一份 `report.md` | 已经写着"没有球场坐标就不给热区" | 不变（本来就对） |

也就是说：**markdown 说的是实话，CSV / JSON / 报告页给的是"所有出手都在篮下 0 米"**。
`rules.shot_chart()` 早就挡住了（所以 `shotchart.json.points` 一直是 0），
但导出与报告这两条路没挡。

## 五、边界（没做的 / 故意的）

- **`x/y` 列仍导出占位坐标**（`0.0 / -1.575`）：这是故意的，方便复核"系统把它放在哪了"，
  同一行的 `tags` 里带着 `location_unknown`；若要求"位置未知就整列空"，那是一句话的事，
  但会丢掉这条可追溯性，所以先保留并在这里写明。
- **`_key_shots` 里的占位出手仍会出现在关键球列表**（事件本身是真的），
  只是不再给区域/距离；前端表格那一列会显示空。
- **滑动标定不参与**：这类出手的位置依然是占位，因为 `adapter.py` 只认**静态** `calibration_valid`。
  要让这类素材出热区，得先解决"滑动标定是否可信"，那是另一件事（见中心锁定文档的优先项 2~4）。
